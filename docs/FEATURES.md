# Fork features

Features this fork added on top of upstream AndCode. The reasoning behind each one is in
[`AGENTIC_CODING_LANDSCAPE.md`](AGENTIC_CODING_LANDSCAPE.md). Token-usage changes have their own
page: [`TOKEN_EFFICIENCY.md`](TOKEN_EFFICIENCY.md).

## Look and feel

| Feature | Where | Notes |
|---------|-------|-------|
| Material You theme | Settings → Appearance → Theme → **Dynamic** | Android 12+. Colors come from the wallpaper and follow the system's light/dark setting. Status colors (running, error, diff tints) keep their fixed meaning. |
| JetBrains Mono for code | everywhere code is shown | Code blocks, diffs, the code viewer, the editor and the terminal. The "NL" cut is used, so `!=` and `->` look as typed. Licensed under OFL 1.1 (Settings → Legal → License texts). |
| Haptic feedback | Settings → Appearance → **Haptic feedback** | Confirm on send, approve, save and commit. Reject on deny and failures. A tick on pinning, and a buzz on long-press. On by default. |
| Screen transitions | – | A short fade-through between screens instead of a hard cut. |
| One design language | Every screen | One card style, spacing and shape scale, grouped settings with icon tiles, consistent top bars, restyled chat and drawer, a welcome screen with a logo hero, and a grouped file explorer (folders first, compact path bar, animated folder changes). |

## Chats

| Feature | Where | Notes |
|---------|-------|-------|
| Search chats | Drawer → search field above **Recent chats** | Matches every word against the chat title and its project folder. Typing opens Recent chats if it was collapsed; clearing the field puts it back as you left it. |
| Search inside messages | Drawer → type in the search field → **Search messages for "…"** | Reads every chat's messages through its agent, a few chats at a time, and lists the chats that contain the text, best matches first, each with a line of context. **Include archived** adds the Archive. A chat that was not changed since the last search is not read again. Tapping a result opens the chat with the same text already in its find bar. |
| Find in chat | Chat → 🔍 in the top bar | Highlights every row that contains the text, shows "3 of 12", and jumps between matches with ↑/↓, starting at the newest. Finds the reasoning and tool calls inside collapsed activity groups too. Back closes it. |
| Pin chats | Long-press a chat in the drawer → pin icon | Pinned chats get their own section at the top. Long-press again to unpin. Auto-archive never touches a pinned chat, and up to two pinned chats also appear as launcher shortcuts. |
| Saved prompts | Settings → Chat → **Saved prompts**; type `/` in the composer | Each saved prompt answers to `/name`. Picking it from the popup puts its text in the composer to edit first; sending `/name` sends the saved text. Arguments work like Claude Code's custom commands: `/fix-issue 123 high` fills `$ARGUMENTS` with everything after the command and `$1`, `$2`… with single words. A prompt without placeholders gets the arguments appended. Picking a prompt that takes arguments from the popup inserts `/name ` so you can type them. A prompt can't take the name of a built-in command. |
| Mention a file | Chat → type `@` in the message box | Lists up to eight project files whose path matches what follows the `@`. Picking one puts `@path/to/file` in the message, which the agent reads as that file. Needs a runtime that can search files; others show no list. |
| Full-screen message | Chat → the expand icon beside the microphone, once a message fills the box | Opens the message full screen for editing. Collapsing or Back returns with every change kept; it survives rotation and starts closed in each chat. |
| Prompts held for a running turn | Settings → Chat → **Send behavior** → **Queue**, then send while a reply is running (Antigravity always holds) | Each one waits above the message box with **Send now** (stops the running turn, where the runtime can interrupt), **Edit** (back into the box with its attachments) and **Remove**, and goes out with its own attachments. |
| Rename a chat | Drawer → long-press a chat → pencil icon, or Chat → ⋮ → **Rename** | Opens on the current name, all selected, so typing replaces it. Works for every agent. OpenCode and Codex keep the name on their side (the session title, the thread name); Claude Code and Antigravity do not name their conversations, so for them it is kept in AndCode's own record of the chat and other clients do not see it. A name you give is never overwritten by the summary Claude Code or Antigravity works out from the first message. A blank name is not saved, and if the agent refuses, the snackbar says why. |
| Delete for real | Drawer → long-press a chat → delete | The chat is gone everywhere, not just hidden: Claude Code's transcript, todos and file history in the runtime, Antigravity's conversation files, the Codex thread and the OpenCode session, plus AndCode's own pin, draft and unread mark. One chat goes at once with **Undo** on the snackbar for 5 seconds; several ask first. If an agent refuses (an older Codex without `thread/delete`, say), the snackbar says why instead of the chat quietly coming back. |
| Archive | Drawer → **Archive**, or Settings → Sessions → **Archived chats** | Every agent's archived chats in one list, newest first, with search. Tap to read one; ⋮ or long-press to **Restore** or **Delete forever** (several at once too), or ⋮ → **Delete all archived**. Archiving from the drawer has Undo. A restored chat counts as fresh for auto-archive, so the next pass does not archive it again. The legacy OpenCode API cannot un-archive, so there a chat can only be deleted. |
| Markdown in messages | Answers, your own messages, and Markdown files under Artifacts | Parsed by commonmark-java (CommonMark plus GitHub tables, task lists, two-tilde strikethrough and footnotes) and drawn by the app: nested lists, `- [ ]` boxes, lists that start at any number, quotes holding lists and code, table columns aligned left, centre or right (physically, also in right-to-left languages), `~~~` and indented code, underlined headings, reference and `<https://…>` links. Bare http(s) links end where Japanese or Chinese text starts. Raw HTML shows as text, except `<br>`, which becomes a line break. Your own messages are drawn the same way, as the agent reads them. |
| Share or copy a chat | Chat → ⋮ → **Share chat** / **Copy as Markdown** | Markdown with one heading per turn, tool calls summarised and reasoning left out. Shared as a `.md` file, so long chats don't hit Android's intent size limit. |
| Restore files to a message | Chat → long-press one of your messages → **Restore files to here** | For on-device agents without their own checkpoints (Claude Code, Codex, Antigravity, OpenCode on the new API): the app snapshots the project folder before each message, in a history of its own outside the folder. Restoring puts changed files back and removes files added since; the messages stay. **Undo** on the banner takes it back. Dependency and build folders (`node_modules`, `build`, …), gitignored files and nested git repositories are never snapshotted and are left as they are; a restore that would overwrite one of them is refused and changes nothing. A project folder that is `/root` or `/` itself gets no snapshots. |
| Changes outside a Git repository | Chat → tap a changes card | When the agent's own diff is empty or missing (a folder that is not a Git repository, or an agent with no diff), the turn's line-by-line diff comes from those snapshots. |
| Open the repository | Chat → ⋮ → **Open on GitHub** | Shown when the chat's project folder was cloned from GitHub (its `origin` points at github.com), on the on-device runtime. Opens the repository page. |
| Copy tool input or output | Chat → expand a tool card → copy icon beside **Input** or **Output** | Each block sits on its own code surface with a copy button that turns into a check mark for two seconds. |
| Find a project | Drawer → 🔍 on the **Projects** header | Filters the project chips by name. **Add project** sits on the same header, so it no longer scrolls off with the chips. |
| Usage readout | Chat → ⋮ | Tokens in and out for the whole chat, plus cost when the runtime reports one (OpenCode does). Cache reads appear on their own line, since they cost a fraction of fresh input. When the runtime priced the turns at nothing (a plan rather than an API key), an estimate at list prices shows beside it. |
| Usage page | Drawer → **Usage** | Tokens and cost across every chat for 7, 30 or 90 days or all time (archived chats optional): totals, chats, turns, daily average and cache hit rate, a day-by-day stacked chart (tap a day for its numbers), the token mix, and breakdowns by model, by agent and by the chats that used the most. Chats are read through their runtimes a few at a time and cached while a chat is unchanged, so the page fills in as they arrive. Claude Code usage is recorded too, and only what a runtime reports is counted. **Estimate at list prices** prices turns the runtime reported as free from a models.dev catalog that ships with the app and refreshes at most weekly when the page opens. |
| Stays live after you leave | Open chat, after the app was in the background | After about 10 seconds or more away, coming back to the app reconnects the live stream at once (it used to wait up to 30 seconds), and the open chat re-reads its transcript, so replies written while you were away show up without reopening the session from the drawer. A short glance away changes nothing. While a reply is running and nothing has arrived for 12 seconds, or the stream is down, the chat catches up from the transcript on its own, less often the longer it stays quiet. A reply that finished while the stream was silent (quiet for 12 seconds or more) is wrapped up straight away. Text the transcript has ahead of the stream is taken; text that is further along on screen is kept, so nothing is lost or doubled. One bad event no longer ends the stream. |
| Run settings | Chat → the tune pill under the message box | One sheet for everything that decides how the next turn runs: agent or permission mode, auto-accept, thinking level, fast mode, Ultracode and the system prompt preset. Each section shows only when the runtime offers it, and changes apply at once. The pill names the mode, thinking level, fast mode and Ultracode, and turns accented when anything differs from a fresh chat. |
| Ultracode | Chat → the tune pill → **Ultracode** (Claude Code) | A switch beside the thinking level: Claude plans the work and runs it as a workflow of several agents, at whatever thinking level is chosen. More thorough, slower, and it uses the account's limits faster. Shown only on a Claude Code model that supports it (not Claude 3, Opus or Sonnet 4.0 to 4.6, or Haiku 4.5), and hidden once a session start shows the account has no workflows. The choice is kept for later chats and starts with the next message, which restarts the session's Claude Code process with `--settings {"ultracode":true}`. |
| Context window (Claude Code) | Chat → tap the context meter | Asks the running Claude Code what fills its context: the total against the window and the auto-compact point, a bar and a row per category, the MCP servers whose tools are loaded (with a button to MCP settings) and the memory files. Before the chat's first message there is no process to ask, and the sheet says so. Codex shows the same sheet with its total against the window, from the usage it reports after each turn, and a **Compact now** button that has Codex summarize the conversation to free space. An instruction file past Claude Code's own size limit is marked large. OpenCode and Antigravity keep the plain meter. |
| Retries, compaction and model fallback (Claude Code) | Chat, while a reply runs | API retries show on the retry card; compacting and a switch to a fallback model show on a run-activity card. Codex's compaction shows the same way. **Stop** ends the whole process tree, for Claude Code and Codex. |
| Pictures from the agent (Claude Code) | Chat | Images a tool or the agent returns show as pictures (tap to open), not as base64 or Claude Code's size note. Finished tools keep their name and input, so Write and Edit cards stay labelled and their files reach Artifacts. |
| Starter prompts | A new, empty chat | Shows the agent's mark, "What should we work on?" and four starters (explain the project, fix a bug, write tests, review changes). Tapping one fills the message box without sending, so you can add the file or symptom first. |
| Changes card and review | Under any answer that edited files → **Review changes** | The card lists the files that answer changed. The review screen shows every file with its +/− counts (tap a file to fold it) and a line-numbered diff. Tap a line to leave a comment; **Send to agent** sends all comments to the chat as one message that names each file, line and the code on it. Needs a runtime that can produce diffs (a Git workspace). |
| Artifacts | Chat → ⋮ → **Artifacts**, or **Preview** on a file in the Changes card | Pages, drawings, documents and pictures the agent wrote (HTML, SVG, Markdown, PNG/JPG/GIF/WebP) open in a full-screen preview: pages run in a sandboxed web view, Markdown renders, pictures show; **Source** flips to the text and Share sends it to another app. Servers AndCode keeps running for the agents (`andcode-run`) are listed first under their names, then local servers the agent started or mentioned (`http://localhost:5173`), each port once; they open in the in-app browser, as do localhost links anywhere in the app. Pages have a **desktop layout** toggle (1280 px wide, zoomed out to fit) and pinch zoom; long Markdown documents and sources are shown whole, block by block and line by line. Files Claude Code writes or edits are listed from the moment the tool starts and stay listed once it finishes; a write that fails drops off. |
| Inbox | Drawer → **Inbox** (the row under the agents counts what waits on you and what is running) | Chats in one list: approvals with Reject / Allow once / Always allow on the card, running chats with their current step and **Stop**, and chats that finished unread with **Reply** and **Mark as read**. Running and finished chats come from every agent; approvals and inline replies are for the selected agent, whose events the app follows (another agent's chat opens instead). A chat waiting on a question shows as running. A reply goes out with the agent and model the chat last used. Tap a chat to open it. |
| Rewind (checkpoints) | Long-press one of your messages → **Rewind to here** (OpenCode chats) | Puts the files the agent changed from that message on back to how they were, hides that message and the ones after it, and returns its text to the message box to send again as is or changed. A banner offers **Undo** until the next message, which makes the rewind permanent. OpenCode restores from snapshots it keeps apart from the project's own git history; it needs a git project, and outside one only the conversation rewinds. Claude Code, Codex, Antigravity and chats on the newer OpenCode protocol have no rewind. |

## Approvals and Claude Code controls

| Feature | Where | Notes |
|---------|-------|-------|
| Risk on approvals | Every approval card | A chip says whether the call only reads, writes, runs a command or is destructive, worked out from Claude Code's tool input, Codex's command or OpenCode's patterns. Destructive covers `rm -r`, `git push --force`, `reset --hard`, `DROP TABLE` and the like, also inside chains and behind `sudo` or `xargs`, and turns the card the error colour. |
| Always allow, per project (Claude Code) | Approval card → **Always allow** | The rule is kept for the project the call ran in and applies there and below, not in a sibling folder. Rules saved before this was added, or without a folder, apply everywhere. A rule never covers a chained command (`git status && rm -rf x`). |
| Every tool of an MCP server | Approval on an MCP tool → **Always allow every <server> tool** (Claude Code) | Kept as `mcp__<server>__*` for the project, whatever the input; it never covers another server. Other runtimes allow the one tool. |
| Blocked commands | Settings → Agents → Claude Code → **Command rules** | Commands Claude Code is never allowed to run: type the first words (`rm -rf`, `git push --force`) or tap a suggestion. A blocked command is refused without asking, also inside a longer command (`cd x && sudo rm -rf /`), with its flags in any order (`rm -fr`, `rm -r -f`) and other words between (`git push origin --force`); the agent is told the user blocked it and not to retry. It applies in every permission mode, Full access included. Flags must be spelled the same (`--force` is not `-f`), and it is a best-effort guard rather than a security boundary: a command that hides its words (through a variable, say) is not caught. The same screen lists the commands allowed with **Always allow** on an approval and removes either kind. |
| Allow by kind | Settings → Agents → Claude Code → **Command rules** → the switches | Lets reading, web or editing tools run without asking, in every project. Commands are never allowed by kind. Editing by kind stays inside the project and away from the hook's rules, `.git`, `.claude` and `.mcp.json`, also through symbolic links. |
| Approval history | Settings → Agents → Claude Code → **Command rules** → **Recent decisions** | The newest 100 decisions: the tool, a short summary of its input, allowed or refused, and how (your answer and the rule it saved, a remembered rule, an allowed kind, a blocking rule, or no answer in time). **Clear** empties it. |
| Keep file edits inside the project | Settings → Agents → Claude Code → **Keep file edits inside the project** | Off by default. Claude Code's Write, Edit and NotebookEdit refuse paths outside the chat's folder, in every permission mode. Shell commands, MCP tools and programs run by hooks can still write anywhere, so it guards against mistakes rather than setting a boundary. Applies from each chat's next message. |
| Checks | Settings → Agents → Claude Code → **Checks** | Two commands Claude Code runs itself: **After each file edit** (after every Write, Edit, MultiEdit or NotebookEdit; keep it quick, like `npm run lint`) and **Before finishing a turn** (like `npm test`). They are the same for every project, run in the chat's project folder and stop after 590 seconds. A failing check's last 80 lines go back to Claude Code, which carries on to fix them; the finishing check lets the turn end after one such round. Adding a check applies from each chat's next message; editing or removing one applies at once. |
| Project instructions | Settings → Agents → Claude Code, Codex or OpenCode → **Project instructions** | Opens the open project's instructions file in the editor, creating it when missing: `CLAUDE.md` for Claude Code, `AGENTS.md` for Codex and OpenCode. A new `AGENTS.md` starts as a copy of the project's `CLAUDE.md`, because OpenCode stops reading `CLAUDE.md` once an `AGENTS.md` exists. |

## Workspace (on-device runtime)

These work on the runtime on this device, where AndCode can run `git` and write files itself. On a
remote PC runtime the buttons stay hidden.

| Feature | Where | Notes |
|---------|-------|-------|
| Code editor | Code viewer → pencil icon | Syntax colours for about 30 file types from a single-pass lexer (multi-line strings and comments, markup with embedded script and style, JSON and YAML keys, CSS properties, Markdown), in the palette of the chosen syntax theme with a matching surface and gutter. Colours as you type, line numbers that follow wrapped lines, current line and matching bracket marked, auto-indent on Enter. A **key bar** above the keyboard: indent and outdent, arrows, line start and end, paired brackets that you step over, symbols, comment toggle, duplicate, delete, move and select line. **Find and replace** inline with match case, whole word and regular expressions with group references, a match count and next/previous from the cursor. Go to line, text size, wrap, and a status bar with line, column, selection, language and indent. Each command is its own undo step; typing still groups by pauses. Save writes the file in place and keeps its mode, so an executable script stays executable. Back with unsaved edits asks first. Files up to 1 MB; the reader stays lazy for big files and colours them the same way. |
| Git panel | Workspace file explorer → the top bar | A full source-control screen: the branch with its upstream, ahead/behind counts, fetch, pull and push; changes split into staged and unstaged with per-file and bulk stage, unstage and discard, conflict markers and a diff viewer; a commit box with amend (with nothing staged, and not amending, it commits everything); paged history with refs and merge markers, and commit details with each file's diff; local and remote branches to switch, create and delete (forced if you choose); stashes to save with a message, pop, apply and drop. Every path, ref, hash and stash name is quoted or validated before it reaches git. |
| Commit | Workspace → Changes → **Commit** | Stages everything (except the `.andcode-attachments` copies AndCode makes for the agent) and commits with your message. A fresh runtime with no git identity commits as `AndCode <andcode@localhost>`. A configured identity always wins. The message is prefilled from the changed files ("Update Main.kt and 2 more files") and selected, so typing replaces it. |
| Discard a file | Workspace → Changes → ↶ on a file | Asks first. A tracked file goes back to its last commit; a new file is deleted. |
| Pull / Push / Stash | Workspace → Changes | Pull is fast-forward only. Push uses `-u origin HEAD`, so a new branch's first push just works. Git's own error text is shown when something fails. |
| Switch / create branch | Workspace → Changes → tap the branch name | This sheet existed before but was never connected. It now lists real branches and switches between them. |
| Recent commits | Workspace → Changes | The last 15 commits. |
| Share a running server | Terminal → the share icon beside a server's chip | After a warning that anyone with the link reaches the server, starts a Cloudflare quick tunnel (no account) and shows a `trycloudflare.com` link to copy, send or scan as a QR code. The tunnel runs like the servers agents start (it keeps the phone awake and shows in the notification with Stop all) and ends when the server stops, the terminal closes, after two hours, or on **Stop sharing**. `cloudflared` is downloaded once, verified against the SHA-256 GitHub publishes for it. |
| Servers that stay up | The agent runs `andcode-run start NAME -- COMMAND`; notification → **Stop all** | Dev servers and watchers an agent starts this way belong to the app, not to the agent's shell. They keep running after the turn, the chat or the agent ends, and the device stays awake while one runs (a notification names them). A crash is restarted up to five times. Each process stops after four hours unless given another limit, and at most five run at once. The agent reads their status, URL and log with `andcode-run list` and `andcode-run logs`. Every agent's built-in instructions (Claude Code, Codex, Gemini, OpenCode) tell it to use this instead of `nohup` or `&`, and to check the server answers before saying it works. They also spell out the single-file rule for artifacts. |
| Processes | Settings → **Processes** | What the agents keep running with `andcode-run`: status, port, **Stop**, **Restart** and live output, plus the processes from last time with **Start** and **Start all**. It also lists any agent instructions file you edited that lacks the `andcode-run` section, with **Add** (keeps your text) and **Dismiss**. |

The command runner now mounts `/workspace` the same way the agents see it. The terminal can reach
it too.

## Browser and DevTools

| Feature | Where | Notes |
|---------|-------|-------|
| Guest Browser | Settings → **Guest Browser**, a local server listed under Artifacts, any localhost link, or a GitHub link in a chat | A browser for the pages the agent serves on the phone. An address pill on top shows the page's title and host (local, secure or not secure) and turns into an address field on tap; controls sit along the bottom within thumb reach; a failed load shows an error screen with Try again; the start screen lists the common dev-server ports one tap away. The ⋮ menu has **Desktop site** (desktop Chrome's user agent, laid out 1280 px wide), **Find in page** with a match count, zoom, reload without cache, copy link and open in the phone's browser. Typed addresses and find results survive page loads. Pages may play media, with sound, without a tap first, also inside a cross-origin embed, so a page the agent opens can play. **Let agents control this browser** (in the ⋮ menu, on by default) lets the agent's `browser_*` tools read and operate the page while the Guest Browser is open; in release builds, with the switch off or the browser closed, they cannot reach it (debug builds keep WebView debugging on for Chrome's inspector, so there the switch does not close it). |
| Agent browser tools | Any agent, while the Guest Browser is open and agent control is on | `browser_read` lists the page's links, buttons, fields and widgets as numbered handles that stay stable across reads; `browser_click` and `browser_type` take a handle; `browser_console` reads console lines, exceptions and failed requests: a failed request's URL has its sign-in details, query values and fragment hidden, but console text is passed on as the page logged it, so a page that logs a secret hands it to the agent. `browser_press_key` and `browser_scroll` do what they say. `browser_read` never shows a password field's value. While an agent drives the page, "An agent is controlling this page" shows over it. |
| DevTools: Console | Browser → DevTools dock under the page (drag to resize) | Every console method, uncaught errors and rejections, levels, filter, collapsed repeats, groups, expandable object trees and stack traces; long-press to copy. A prompt runs JavaScript in the page (promises included) with command history. |
| DevTools: Network | same | `fetch`, XHR and WebSocket traffic with headers, payloads, responses (JSON pretty-printed and browsable) and frames, plus every other resource from resource timing. Type chips, failed-only, preserve log, a waterfall, and copy URL / as cURL / response. |
| DevTools: Elements | same | A lazily loaded DOM tree, tap-to-inspect on the page with a highlight overlay, matched CSS rules, computed styles, a box-model diagram and outer HTML; attributes can be edited and elements deleted. |
| DevTools: Storage, Sources, Performance | same | Local storage, session storage and cookies, editable. Every script and stylesheet, readable with line numbers. A load timeline, paint and load metrics, heap, DOM size, resource totals and the page's environment. |

A small page agent (`assets/devtools/andcode-devtools.js`) is installed as a document-start script
and reports to the app over a WebMessage listener, using `androidx.webkit` (Apache-2.0, listed in
the notices). DevTools only report on pages in the Guest Browser.

## Storage

| Feature | Where | Notes |
|---------|-------|-------|
| Storage manager | Settings → **Storage** | What AndCode uses against the device's free space, as one stacked bar, then a breakdown that adds up to the total without counting anything twice: projects, attachments, agents, agent data, the Linux environment, caches, logs, install leftovers, temporary files, the update backup, the voice model and everything else. **Clean up** frees caches, logs and the leftovers of unfinished installs, per area or all at once, after a confirmation; the update backup, agents, agent data and projects are never offered. A **folder browser** opens any folder sorted by size, with a Largest files list; projects and cleanable places can be deleted there after a confirmation, everything else shows as managed by the app. |

Cleaning is built not to hurt a working install: it refuses while a chat, a scheduled run, an install
or an update is at work (and checks again before each folder), never follows a symbolic link out of
the app's folders, keeps the `.l2s.*` files PRoot uses to emulate hard links (projects can point into
them), and inside the Linux environment only touches package caches known to copy rather than link
(`.npm/_cacache`, `.npm/_logs`, `.cache/pip`). Folders outside it are renamed into a trash folder
before they are deleted, so one an install creates again a moment later is left alone.

## Launcher and system

| Feature | Where | Notes |
|---------|-------|-------|
| App shortcuts | Long-press the app icon | Up to two pinned chats, then New chat, Workspaces and Schedules, cut to as many as the launcher shows. Ignored until onboarding is done. |
| Quick Settings tile | Edit Quick Settings → **AndCode prompt** | Opens the quick-prompt box from the home screen widget. Asks you to unlock first. |
| Schedule templates | Schedules → new schedule → **Start from a template** | Daily change summary, weekly dependency check, nightly test run, TODO sweep, monthly security review. Each one fills in the name, prompt and timing. Templates are only offered for a new schedule. |
| Run a schedule from another app | Schedules → the ⚡ icon (**Run from other apps**) | Tasker or any app can run a schedule by sending the broadcast `com.yugahashimoto.andcode.TRIGGER_SCHEDULE` to this app with the schedule's id and your token. Off until you create a token there; the screen shows the package, action, token and each schedule's id to copy, and a new token revokes the old one. A schedule that is off is not run. |
| Live run notification | Notification shade, while a chat runs | One silent, ongoing notification: the chat's title, its agent and the step in flight ("bash · ./gradlew test"), a running clock and **Stop**. Several running chats share one notification that lists each. Subagent sessions are left out; their parent stands for them. Its own channel, **Running chats**, can be turned off in Android's notification settings. |
| Reply from a notification | "Chat finished" and "Chat failed" notices → **Reply** | Type the next instruction in the shade; it is sent to that chat and the live notification takes over. If sending fails, the notice comes back with Reply on it. Approval notices already have Allow once, Always allow and Reject. |
| App lock | Settings → Privacy → **Require unlock to open** | Off by default. Asks for the phone's fingerprint, face or screen lock (PIN, pattern, password) when the app opens and when it comes back after more than 30 seconds away, so the share sheet or a browser sign-in does not ask again. Turning it on does not lock what is already open, and rotating the screen never unlocks it. **Also require it to send a message** asks again before each message, review and Inbox reply goes out; cancelling keeps the text. The recents thumbnail is hidden while the lock is on (before Android 13 this also blocks screenshots of the app, the only way those versions offer). While the lock is on, nothing outside the app acts for you except **Stop** on the live notification, which only ends a run: notifications have no Reply or Allow/Reject (tapping opens the locked app) and show no details on the lock screen unless Android is set to show sensitive notification content there, the home-screen widget and the Quick Settings prompt open the app instead of sending, and the voice assistant, which can open over the lock screen, sends nothing while the phone itself is locked. Needs Android 9 or later; on a phone with no screen lock the switch is greyed out with the reason. |
